## 步骤 3.3 — Phase 2：serialization 去 draw 依赖 + 判定下沉

**目标**：serialization 仅依赖 utilities，彻底去掉对 draw 的引用；值包判定下沉为下层事实，由 draw 复用（设计文档 §2.6 D6）。

> **校订**：原方案让 serialization 自带一套、draw 留一套，"接受 2 行重复"。判定下沉后**单一来源保留**——`draw → serialization` 方向合法，无需重复。

### 3.3.1 值包判定下沉（替代"各自实现"）
- `RD.Serialization`（Runtime）提供 `public static bool IsUnityValueBagType(Type type)`：仅 `AnimationCurve` / `Gradient`。
- draw 侧 `DefaultTypeShape.IsUnityValueBagType` 改为**转发**下层判定；`Engine.IsUnityValueBagType` 保留公开（转发），以免破坏既有调用方。
- **注释同步（易漏）**：`Engine.IsUnityValueBagType` 的 XML 注释现写"宿主 serialization 要跟引擎用同一条判定，不能各写一份"，`DefaultTypeShape` 注释写"全仓仍只有一份实现"——二者都描述旧决策，必须改写为"转发 `RD.Serialization` 判定"。

### 3.3.2 `SerializedScriptableObject` —— **决议：维持 Editor 侧，不下沉**
原计划迁到 `Runtime/`，实施时撞到两处硬约束：
1. 它的数据读写调用 `Serialization.Serialize/Deserialize`，而 JSON 内核在 Editor 程序集；下沉它就得连内核一起搬（内核还带着 Editor 侧的日志通道）。
2. 它自身定位是**编辑器数据资产载体**（类注释原文），`[CustomEditor]` 登记在 inspector（Editor），消费方 packagemanager 也是 Editor 包 —— 没有运行时使用场景。

因此 **Runtime 只承载 `[Serialize]` 与值包判定**（这两样才是 Runtime 与绘制两侧真正共用的"数据事实"），资产载体与内核留在 Editor。若日后真要运行时可用的载体，再连内核一起下沉，另立文档。

### 3.3.3 去掉引用
- serialization 的 Editor asmdef 去掉 `RD.Draw` / `RD.Draw.Editor`，加 `RD.Serialization`；`package.json` 去掉 `cn.rendu.draw`，保留 `cn.rendu.utilities`。
- **`Scripts/Editor/Share/AssemblyReference.asmref` 复核**：三个包（serialization / inspector / edittool）都有该文件指向 init 包的 `RD.Editor`，`Share/` 下源码不进本包程序集。本包清零后仍编译失败的话，问题多半在 `Share/`——单独 grep 确认其无 `RD.Draw` 引用。

### 3.3.4 版本号定夺 —— **本次未改（遗留）**
- 既有不自洽：`cn.rendu.draw/package.json` 是 `0.0.0`，而 serialization / edittool / inspector / packagemanager 都声明 `"cn.rendu.draw": "3.0.0"`。
- 本次新增的依赖一律写**实版**（`cn.rendu.serialization: 1.0.0`），没有再造一个对不上的版本号；既有声明未动 —— 抬 draw 版本或改声明属发布策略，留给发布时统一决定。

### 3.3.5 验证
- grep：serialization 内 `RD.Draw` 引用清零（含 `Share/`）；serialization 仅依赖 `RD.Utilities`。
- 编译：全仓通过。
- 行为：序列化/反序列化结果与改造前一致（可对比样例资产往返）。
- 拓扑校验：`utilities → serialization → draw → {edittool, inspector}`，无环。

### 3.6.1 维持现状并补注释

- 注意该 `HelpBox` **必须挂在引擎容器之外**——后端按位置复用元素，混进去会被当成第一个控件换掉（此约束写进代码注释）。

### 3.6.2 验证
