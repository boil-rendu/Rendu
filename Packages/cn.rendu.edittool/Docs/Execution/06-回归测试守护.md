## 步骤 6.1 — S5：值包判定的回归测试守护

**目标**：`RD.Serialization.IsUnityValueBagType` 是唯一实现，draw 侧只转发——守护"转发不漂移"。

> **校订**：原方案是"serialization 自带一份、draw 留一份，测试对照两份实现"。判定下沉（§2.6 D6）后不再有两份实现，测试从"对照"改为"验证转发一致"。

### 6.1.1 写测试
- 位置：`cn.rendu.serialization/Tests/`（EditMode）。
- 用例：
  - `AnimationCurve` / `Gradient` → `RD.Serialization.IsUnityValueBagType` 返回 `true`。
  - 普通类型（`int` / `string` / 自定义类 / `List<T>`）→ 返回 `false`。
  - **转发一致性**：对同一组类型，`RD.Draw.Editor.Engine.IsUnityValueBagType` 与 `RD.Serialization.IsUnityValueBagType` 结果逐一相等（确保 draw 侧没另起一份实现）。
  - 往返：序列化一个含 `AnimationCurve` 字段的资产（序列化 → 反序列化）值不变。

### 6.1.2 守护约定（文档）
- 判定归属：**数据事实归 serialization**（"AnimationCurve / Gradient 是 Unity 原生值包"脱离 UI 也成立）；draw 只保留"渲染形态分类"（容器 / 标量 / 可内联），值包一条复用下层。
- 若发现 draw 侧出现第二份判定实现 → 视为回归，改回转发表。
